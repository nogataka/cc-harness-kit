# docs ページの書き方

`skills/setup/` と `skills/audit/` の各スキルに、人向けの説明ページを `docs/<バケット>/<スキル名>.md` として置きます。ページは `SKILL.md` の写しではありません。読む人が「これは何をするか」「いつ使うか」を短時間で判断できるようにするためのものです。

スキルを追加、改名、または挙動を変更したときは、対応するページも同じ変更の中で更新します。改名はファイルも移動します。

## 構成

次の4節を、この順で書きます。見出しは h2 です。H1 は置きません。

### What it does

1〜2段落。最初の一文でスキルの仕事を言い切ります。続けて、このスキルが既定の振る舞いと違う点を1つ書きます（例: `harness-claudemd` は CLAUDE.md を生成するが、既存ファイルがあれば diff を提案書に出すだけで上書きしない）。

### When to reach for it

- 起動方法。user-invoked なら「`/名前` と打ちます。Claude が自分で開くことはありません」。model-invoked なら「`/名前` と打つか、Claude が必要と判断したときに開きます」。
- 使う場面と、使わない場面。近い役割のスキルがあれば、どちらを選ぶかの境界を1行で書きます。

### Common questions

実際に出そうな質問を太字で書き、答えを下に書きます。数は根拠のある分だけにします。質問が思い当たらなければ節ごと省きます。

### It's working if

スキルが正しく動いたときに、読者が自分の環境で確認できる兆候を箸書きにします。`SKILL.md` を開かずに確かめられるものだけを書きます。

## 規則

- 手順の再掲はしません。手順は `SKILL.md` にあります。
- です・ます調。英略語の見出し、絵文字は使いません。
- リンクは相対パスで、リポジトリ内で解決できるものだけを貼ります。
- インストール手順はページに書きません。`README.md` に集約します。
