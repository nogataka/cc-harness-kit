# user-invoked と model-invoked

このリポジトリの `SKILL.md` は、誰が起動できるかで2種類に分かれます。

- **user-invoked**: 人が `/名前` と打ったときだけ動きます。フロントマターに `disable-model-invocation: true` を置きます。`description` は人がスラッシュコマンド一覧で読む一行要約として書き、「〜と言われたときに使う」のような発火条件は書きません（自動発火には使われないため）。`skills/setup/` のスキルはすべてこちらです。対象リポへの書き込みを伴うため、人が意図して始めるべきだからです。
- **model-invoked**: 人も Claude も起動できます。`disable-model-invocation` を書きません。`description` は Claude が「今これを開くべきか」を判断する材料なので、依頼文に含まれそうな語を先頭に置きます。`skills/audit/harness-audit` だけがこちらです。読み取り専用で副作用がないためです。

判定基準は「Claude が自律的に開いて役に立つか、かつ副作用がないか」です。両方を満たすときだけ model-invoked にします。

## スキル間の依存

- setup スキルの手順の中で `harness-audit` を使うときは、「Skill ツールで `harness-audit` を呼ぶ」と書きます。`/harness-audit` と書くだけでは Claude がコマンドとして解釈しない場合があります。
- user-invoked のスキルを別のスキルから呼ぶことはできません。`harness-init` が各層のスキルへ進めるときは、「次に `/harness-claudemd` を実行してください」と人に案内する文で書きます。Skill ツールで呼ぼうとしないでください。
- 参照資料は、それを使うスキルのディレクトリ内に置きます。別のスキルのファイルを `../` で参照しないでください。

## 共通の本文構造

setup スキルの本文は次の順で書きます。

1. 目的（1段落）
2. 探索（対象リポの何を読むか）
3. 提案書の作成（書式は `templates/proposal.md` に従う）
4. 承認待ち（ここで止まる。承認なしに次へ進まない）
5. 書込（承認された項目だけ。既存ファイルは `.claude/harness-kit/backup/` へ退避してから編集）
6. 確認（書込後に何を見て成功と判断するか）

## `description` の長さ

複数のスキルが並ぶと `description` は短く切られます。先頭の一文（層の番号と、何を整えるか）だけで用途が分かるように書き、全体は 200 文字以内を目安にします。
