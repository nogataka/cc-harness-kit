# ADR-0003: 設定ファイルは起動ディレクトリに置く

日付: 2026-09-05 / 状態: 採用

## 背景

Claude Code の公式ドキュメント（Set up Claude Code in a monorepo or large codebase）によると、CLAUDE.md は起動ディレクトリから親へ向かってすべて読み込まれますが、`.claude/settings.json` は起動ディレクトリのものだけが読まれ、親ディレクトリから継承されません。

大規模リポでは「作業するパッケージのディレクトリから起動する」運用が推奨されています。このとき、リポジトリルートの `.claude/settings.json` に置いたフックや読み取り拒否ルールは効きません。

## 決定

- setup スキルは、生成する設定ファイルの置き場所を **起動ディレクトリの `.claude/settings.json`** に固定します。
- 探索の最初に「このリポではどのディレクトリから起動する運用か」を確認し、提案書の冒頭に明記します。ルートとサブディレクトリの両方から起動する運用なら、両方に設定を置く提案にします。
- フックのスクリプトパスは `${CLAUDE_PROJECT_DIR}` で始めます。起動ディレクトリを基準に解決されるため、サブディレクトリ起動でも迷子になりません。
- `harness-audit` は、起動ディレクトリ基準で設定ファイルの所在を報告し、「ルートに設定があるがサブディレクトリ起動の運用」という不整合を検知します。

## 帰結

- 同じ設定を複数ディレクトリに持つ場合があります。重複を避けたい場合は、共通部分をプラグイン（第4層）に寄せる案を提案書に添えます。
- CLAUDE.md は継承されるので、この ADR は CLAUDE.md には適用しません。CLAUDE.md はルートとサブディレクトリの2段構成にします。
- サブディレクトリ起動が難しく、ルートからしか起動できない運用を選んだ場合は、他チームや触らない領域の CLAUDE.md を `claudeMdExcludes` で除外する案を `harness-claudemd` の提案書に添えます。`claudeMdExcludes` は `.claude/settings.json`（チーム共有）または `.claude/settings.local.json`（個人）のどちらに置くか、提案書で選ばせます。CLAUDE.md の継承（親から子へすべて読み込まれる）とこの ADR の起動ディレクトリ基準（`.claude/settings.json` は継承されない）は別の仕組みのため、`claudeMdExcludes` は本 ADR の「起動ディレクトリ基準」を補う別の緩和策と位置づけます。
