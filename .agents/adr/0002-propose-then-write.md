# ADR-0002: 探索、提案書、承認、書込の順を崩さない

日付: 2026-09-05 / 状態: 採用

## 背景

setup スキルは対象リポの CLAUDE.md や `.claude/settings.json` を生成・編集します。これらは全セッションの挙動を変えるファイルで、壊すと影響が大きい一方、壊れたことに気づきにくいです。

## 決定

すべての setup スキルは次の順で動きます。

1. **探索**: 対象リポを読み、現状を把握します。書き込みはしません。
2. **提案書**: 変更案を `harness-proposal-<層>.md` に書き出します。書式は `templates/proposal.md` です。既存ファイルへの変更は diff 形式で示します。
3. **承認待ち**: ここで止まります。人が提案書を読み、採用する項目を選びます。
4. **書込**: 承認された項目だけを書き込みます。既存ファイルを編集する前に、`.claude/harness-kit/backup/<日時>/` へ元のファイルを退避します。
5. **確認**: 書込後の確認手順を実行し、結果を報告します。

## 禁止事項

- 既存の CLAUDE.md、`.claude/settings.json`、`.claude/rules/*`、`.claude/skills/*` を、提案書なしに上書きしないでください。
- 承認された範囲を超えて「ついでに」直さないでください。気づいた点は提案書の末尾に「追加の提案」として書くだけにします。
- 退避なしに既存ファイルを編集しないでください。

## 帰結

- 1回の実行で人の確認が1回入ります。速さより安全を優先した設計です。
- 提案書は承認後に消してよいファイルです。`.gitignore` への追加を `harness-init` が案内します。
