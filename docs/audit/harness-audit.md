## What it does

`harness-audit` は、対象リポのハーネスを7層で採点します。起動時に読み込まれる CLAUDE.md の行数、下位ディレクトリの CLAUDE.md、強い語や番号付き手順の行数、起動ディレクトリの設定ファイルとフック、スキルと rules、プラグイン、検出言語ごとの LSP の状態、除外、オーナー文書を1枚の Markdown にまとめます。読み取り専用で、ファイルを変更しません。

## When to reach for it

`/harness-audit` と打つか、Claude が「CLAUDE.md が長い」「フックが効いていない」といった相談を受けたときに自分で開きます。

- 現状を知りたいとき、見直しの前後で比べたいときに使います。
- 何かを直したいときは、採点表の末尾に案内される setup スキルへ進みます。

## Common questions

**ルートの設定ファイルがあるのに「起動ディレクトリにありません」と出ます。**
`.claude/settings.json` は起動ディレクトリのものだけが読まれます。サブディレクトリから起動しているなら、ルートの設定は効いていません。レポートの第2層に注意が出ます。

**起動ディレクトリを引数で指定したいです。**
自動実行される監査レポート（`!` 行）は、引用符のエスケープが確定できないため、カレントディレクトリしか対象にしません。同じリポ内の別ディレクトリを監査したいときは、レポートに頼らず Bash ツールで次を直接実行してください（`allowed-tools` で事前承認済みです）。

```
${CLAUDE_SKILL_DIR}/scripts/harness-audit.sh <起動ディレクトリ>
```

**別のリポの中に置いた検証用ディレクトリを監査したいです。**
`git rev-parse` が外側のリポをルートと判定します。環境変数 `HARNESS_AUDIT_ROOT` に検証用ディレクトリを渡してください。

**`.claudeignore` が警告されました。**
Claude Code の正式機能ではないため効いていません。除外は `.gitignore` と `permissions.deny` で行います。

## It's working if

- レポートの末尾に、層ごとの「充足 / 一部 / 未着手」の採点表が出ます。
- 起動ディレクトリを変えて実行すると、読み込まれる CLAUDE.md と設定ファイルの所在が変わります。
- 同じリポで見直しの前後に実行し、行数や件数の差が読み取れます。
