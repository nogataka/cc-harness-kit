## What it does

`harness-lsp` は、対象リポの言語を検出し、公式マーケットプレイスのコードインテリジェンスプラグインを有効にします。有効になると Claude は編集直後に型エラーや import 漏れの診断を受け取り、定義ジャンプや参照検索をシンボル単位で行えます。言語サーバのバイナリは人が入れるものなので、未検出の言語については導入手順を案内して止まります。

## When to reach for it

`/harness-lsp` と打ちます。Claude が自分で開くことはありません。

- 監査の第5層で、検出言語にプラグインが有効化されていないときに使います。
- 多言語のコードベースや、C/C++、Java のように文字列検索で同名シンボルを取り違えやすい言語では効果が大きいです。

## Common questions

**プラグインを入れたのに `Executable not found in $PATH` と出ます。**
プラグインは接続設定だけで、言語サーバ本体は含みません。対応表のバイナリを PATH に入れてください。

**メモリを多く使うようになりました。**
rust-analyzer や pyright は大きなプロジェクトで重くなります。`/plugin disable <プラグイン名>` で外し、内蔵の検索に戻せます。

**クラウドセッションで LSP が使えません。**
クラウドセッションではプラグインの言語サーバが起動しません。ローカル実行時だけの機能です。

## It's working if

- `/plugin` の Errors タブに何も出ていません。
- 対象言語のファイルを編集すると「Found N new diagnostic issues」の表示が出ます。
- 故意に型エラーを入れると、Claude が同じターンで気づいて直します。
