## What it does

`harness-claudemd` は、対象リポの CLAUDE.md をルートとサブディレクトリの2段に整え、各ファイルを 200 行未満に近づけます。既存の CLAUDE.md を上書きすることはなく、削除・書き直し・移動・追加の案を提案書に diff で出し、承認された項目だけを書き込みます。

## When to reach for it

`/harness-claudemd` と打ちます。Claude が自分で開くことはありません。

- CLAUDE.md が 200 行を超えている、禁止ルールが並んでいる、手順や日付付きのメモが溜まっている、パッケージごとの規約が1つのファイルに混ざっているときに使います。
- 手順をスキルに切り出す作業そのものは [harness-skills](harness-skills.md) が行います。このスキルは「どの行を移すか」を申し送ります。

## Common questions

**何を「自明」として削るのですか。**
設定ファイルや `ls` で分かること、つまり技術スタックの列挙、ディレクトリ構成、リンターが強制している規約です。「やってみたら失敗した」という罠や、ツールの既定と異なる規約は残します。

**禁止ルールは全部書き直されますか。**
いいえ。不可逆な操作（削除、履歴の書き換え、本番反映、外部送信、課金）と組織・契約上の制約は禁止形のまま残します。コーディングスタイルの禁止だけを「周囲に合わせる」形に直します。

**ルートからしか起動できない場合はどうなりますか。**
`harness-init` で「ルートから起動せざるを得ない」と答えると、その旨がこのスキルへ申し送られます。探索で他チームや触らない領域のサブディレクトリ CLAUDE.md を一覧化し、`.claude/settings.json` の `claudeMdExcludes` にそれらのパスを列挙する案として提案書に載せます。設定の置き場所（個人の手元だけで除外するなら `.claude/settings.local.json`、チーム全体で共有するなら `.claude/settings.json`）も提案書の中で選べます。

## It's working if

- 提案書の冒頭に、各ファイルの「現在の行数 → 適用後の見込み行数」が表で出ます。
- 承認後に `/context` を見ると、Memory files に意図したファイルだけが載っています。
- `.claude/harness-kit/backup/` に変更前のファイルが残っています。
