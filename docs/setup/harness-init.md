## What it does

`harness-init` は、対象リポのハーネスを構築順で組み立てるための司令塔です。監査を実行し、未充足の層のうち最初の1つについて、次に実行するスキルを案内します。自分では何も書き込みません。1回の実行で案内する層は1つだけで、全部を一気に進めることはしません。

## When to reach for it

`/harness-init` と打ちます。Claude が自分で開くことはありません。

- 初めて対象リポにハーネスを入れるとき、または久しぶりに見直すときに使います。
- 現状だけ知りたいなら [harness-audit](../audit/harness-audit.md) を使います。
- 直したい層が分かっているなら、その層のスキルを直接実行して構いません。

## Common questions

**なぜ1層ずつしか進まないのですか。**
各層は前の層を土台にします。CLAUDE.md が肥大したままフックやプラグインを足しても効きません。1層ごとに提案と承認を挟むことで、途中で止めても壊れた状態にならないようにしています。

**起動ディレクトリを聞かれるのはなぜですか。**
`.claude/settings.json` は起動したディレクトリのものだけが読まれ、親から継承されません。作業するパッケージから起動する運用なら、設定はそのパッケージに置く必要があります。

## It's working if

- 実行後に「次は `/harness-〇〇` を実行してください」という案内が1つだけ出ます。
- 案内の理由が、監査の採点表の行を引いています。
- 全層が充足していれば、次回の見直し日と溜まっている追記候補の件数が表示されます。
