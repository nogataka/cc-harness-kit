# 第1層: CLAUDE.md を階層化する

対象: `$ARGUMENTS`（空ならカレントディレクトリ）

CLAUDE.md は毎セッションの土台です。ここが肥大していると、他の層をどう整えても効きません。このスキルは既存の CLAUDE.md を**黙って上書きしません**。提案書に diff を出し、承認された項目だけ書き込みます。

## 探索

1. Skill ツールで `harness-audit` を呼び、第1層の節（起動時に読み込まれるファイル、下位 CLAUDE.md、点検対象の行数）を確認します。
2. 起動時に読み込まれる CLAUDE.md をすべて読みます。各行を次の5分類に振ります。
   - A 目的（何のリポか）
   - B 環境の注意点（見ても分からない罠。最も価値が高い）
   - C 禁止ルール・行動規範（「〜しないこと」「必ず〜」）
   - D 手順・チェックリスト（番号付きの手順、レビュー・リリース手順）
   - E 覚え書き・仕様の本文（日付付きのメモ、API 仕様）
3. 設定ファイル（`package.json`、`pyproject.toml`、`tsconfig.json`、lint 設定）を読み、CLAUDE.md の記述と重複しているものを A〜E とは別に「自明」として印を付けます。
4. `packages/`、`apps/`、`src/<サブシステム>/` のように領域が分かれているか確認します。分かれているなら、各領域に CLAUDE.md があるかを見ます。
5. `harness-init` から「ルートから起動せざるを得ない」という申し送りがあれば、他チームや触らない領域のサブディレクトリ CLAUDE.md の一覧を控えます（`claudeMdExcludes` の候補にします）。

## 提案書

`harness-proposal-claudemd.md` を起動ディレクトリに書き出します。書式は同梱の `templates/proposal.md` です。内容は次の4種類に分けます。

| 種類 | 対象 | 提案の形 |
|---|---|---|
| 削除 | 自明な記述（技術スタックの列挙、ディレクトリ構成、リンターが強制する規約）、重複行 | diff で削除行を示す |
| 書き直し | C 分類。「〜するな」を「何に合わせるか、何を優先するか」に | 現在の文と提案文を並べる。不可逆操作（削除、履歴の書き換え、本番反映、外部送信、課金）と組織・契約上の制約は禁止形のまま残す |
| 移動 | D 分類は `/harness-skills` へ、E 分類のうち仕様の本文は別ファイルへ、個人的な覚え書きは自動メモリへ | 移動先と、CLAUDE.md に残す1行を示す。このスキルでは移動先ファイルを作らず、次のスキルへの申し送りにする |
| 追加 | 領域ごとの CLAUDE.md（`templates/claude-md/subdir.md`）、ルートが無ければ `templates/claude-md/root.md`、構造から役割が読めなければ `templates/claude-md/codebase-map.md` | 全文を提案書に載せる。テンプレートの `<...>` は探索で得た内容で埋め、埋められない箇所は空のまま `<未記入>` と残す |

提案書の冒頭に、各ファイルの「現在の行数 → 提案適用後の見込み行数」を表で載せます。200 行を超えるファイルが残るなら、その理由を書きます。

`harness-init` から「ルートから起動せざるを得ない」という申し送りがある場合は、提案書に次を追加します。

- 対象: 探索で控えた、他チームや触らない領域のサブディレクトリ CLAUDE.md の一覧
- 設定: `.claude/settings.json` の `claudeMdExcludes` にそれらのパスを列挙する案
- 置き場所: 個人の手元だけで除外したいなら `.claude/settings.local.json`、チーム全体で共有するなら `.claude/settings.json`。どちらにするか提案書で人に選ばせます。

## 承認待ち

提案書を書いたら止まり、人に次を伝えます。

> `harness-proposal-claudemd.md` を書きました。採用する項目の `[ ]` を `[x]` にして「承認」と言ってください。全部でも一部でも構いません。

承認の言葉を受け取るまで書き込みません。

## 書込

1. 変更・削除の対象になる既存ファイルを `.claude/harness-kit/backup/<YYYYMMDD-HHMMSS>/` に、元のパス構造のままコピーします。
2. `[x]` の項目だけを適用します。`[ ]` の項目は触りません。
3. 適用後、各 CLAUDE.md の行数を数え、提案書の見込みと比べます。

## 確認

- `/context` を実行し、Memory files の欄に意図したファイルだけが載っていることを人に確認してもらいます。
- 移動として申し送った項目があれば、「次は `/harness-skills` を実行してください」と案内します。
- 提案書は消してよいことを伝えます。

## 補助ファイル

- `templates/proposal.md`: 提案書の書式
- `templates/claude-md/root.md`, `subdir.md`, `codebase-map.md`: 追加時のテンプレート
