# ハーネス監査

対象: カレントディレクトリ（`$ARGUMENTS` が指定されていても、自動実行の `!` 行には展開しません。引用符のエスケープが Claude Code 側でどう扱われるか確定できないため、安全側に倒しています）。

## 監査レポート（カレントディレクトリを自動監査）

!`${CLAUDE_SKILL_DIR}/scripts/harness-audit.sh`

別のディレクトリを対象にしたい場合（`$ARGUMENTS` に起動ディレクトリが渡された場合を含む）は、上のレポートに頼らず、Bash ツールで次を実行してください（`allowed-tools` で事前承認済みです）。

```
${CLAUDE_SKILL_DIR}/scripts/harness-audit.sh <起動ディレクトリ>
```

## このレポートの読み方

上の採点表を、次の観点で人に説明してください。ファイルの書き込みは行いません。

1. **未着手の層を構築順に並べる**。第1層 CLAUDE.md が「一部」以下なら、他の層より先にそこを直すよう勧めます。各層は前の層を土台にするためです。
2. **設定ファイルの所在**。第2層に「ルートの設定はこのディレクトリから起動した場合には読み込まれません」の注意があれば、最初に伝えます。設定が効いていない状態だからです。
3. **第1層の点検対象の行**。強い語の行数、番号付き手順の行数、重複行数を示し、それぞれ「判断基準への書き直し」「スキルへの切り出し」「1か所への統合」が候補だと説明します。
4. **第5層 LSP**。検出言語ごとに、バイナリの有無とプラグイン有効化の有無を分けて伝えます。バイナリの導入は人が行う作業です。
5. **除外**。`.claudeignore` の警告が出ていれば、効いていないことを明確に伝えます。

最後に、次に実行するスキルを1つだけ勧めます。

| 最初に直す層 | 勧めるスキル |
|---|---|
| 第1層 | `/harness-claudemd` |
| 第2層 | `/harness-hooks` |
| 第3層 | `/harness-skills` |
| 第4層 | `/harness-plugin` |
| 第5層 | `/harness-lsp` |
| 除外 | `/harness-exclusions` |
| オーナーシップ | `/harness-ownership` |
| 全体を順に進めたい | `/harness-init` |

これらは人が起動するスキルです。Skill ツールで呼ばず、「次に `/harness-claudemd` を実行してください」と案内してください。

## 補助ファイル

- `scripts/harness-audit.sh`: レポート生成（読み取り専用）。手動実行は `bash <このスキルのディレクトリ>/scripts/harness-audit.sh <起動ディレクトリ>`。
